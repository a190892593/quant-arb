## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 归档节点成本 | R1 默认关闭 | 配置门控，不配置即回退到已记录复算 |
| 跨 tick 拖慢扫描 | R3 影响扫描周期 | 超时 + top 池限制 + 失败降级 |
| 干跑与真实执行差异 | R2 结论误用 | 明确标注"未签名/未广播" |
| 聚类误判 | R4 画像失真 | 标注概率识别，不宣称机器人身份 |
| 模拟入账影响账本 | R5 数据污染 | 先隔离表再入账，权益恒等式测试 |

## 执行顺序（建议）

1. R2（不依赖外部资源，最快落地）
2. R1（门控开发，无归档节点也能验证 UNAVAILABLE 分支）
3. R4 → R5（采集增强 → 入账）
4. R3（需要额外 RPC 调用，放后）
5. R6（依赖 R4/R5 数据）
