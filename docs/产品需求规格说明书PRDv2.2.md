## 1. 项目定位与竞争目标

### 1.1 产品定位

面向 Base 和 Arbitrum 的 DEX 原子套利研究、实时扫描、竞争分析和 Paper Trading 系统。

系统不是简单发现两池价差，而必须回答十个问题：

1. 路线是否真实存在套利空间？
2. 不同资金规模下是否仍盈利？
3. 扣除全部成本后还剩多少？
4. 是否有其他机器人参与？
5. 竞争者通常何时成交？
6. 机会平均存活多久？
7. 我们是否有足够时间完成发现与模拟？
8. 竞争需要付出多少费用？
9. 竞价后是否还有利润？
10. 该机会应参与、观察还是放弃？

### 1.2 核心竞争策略

**低竞争机会优先，高净利润优先，避免无条件参与热门路线的速度竞赛。**

同时具备两种能力：

- 热门机会监测：了解最活跃路线与竞争者；
- 低竞争机会挖掘：发现竞争者覆盖少但流动性/利润足够的路线。

低竞争不等于有价值，必须经流动性、资金容量、Token 风险、成本、模拟验证。

### 1.3 收益目标（研究目标，非承诺）

- 年化收益 100% 以上的**可行性研究**；
- 资金规模 5,000–100,000 U 的**潜在容量研究**；
- 首期验证 250–10,000 U 档位；
- 5,000 USDC 等值标准审计本金。

**年化与容量均为研究目标，不构成保证收益或验收承诺。**

### 1.4 北极星指标与明确非目标

北极星：**扣除全部成本后的单位时间风险调整净利**（每周期/每日），不是毛利润或路线数。

非目标：不比所有机器人快、不做 CEX–DEX、不做 6–8 跳、不做 BSC/Thena、不做链上盲目探测、不开放实盘、不承诺年化、不调低风控门槛制造样本。

## 4. 实时数据接入与链上状态引擎

### 4.1 目标

减少状态更新延迟、数据遗漏、过期报价、全量刷新重复计算、RPC 请求积压。

### 4.2 接入方式

HTTP RPC、WebSocket、区块订阅、日志订阅、批量 `eth_call`、必要时历史区块读取。实时数据与历史数据分开管理。公共与付费 RPC 均纳入健康管理。

**链级接入约束（强制）：**

- **Base**：Denim 升级后为 **200ms 原生区块**（每秒 5 个正式区块）。实时数据必须基于**正式区块**的 `newHeads` + 日志订阅构建。
  **禁止再采用旧 Flashblocks WebSocket / pending 预确认状态作为实时数据基础**——Flashblocks 已被 Denim 取代，
  不得作为 Base 实时模块的设计依据。200ms 只是区块节奏，不等于 200ms 完整反应时间，也不保证交易进入下一个区块。
- **Arbitrum**：区块约 250ms，每个区块包含两个约 125ms 的优先级排序轮次（PGA）。Fast Feed 只用于**观察已排序交易**，
  它不是未排序内存池，不能让后来提交的交易插到已确定顺序的交易前面；据此设计提交时机与竞价，
  而不是"提前看到所有待处理交易"。

### 4.3 数据同步功能

新区块检测、Pool 事件监听、Pool 状态刷新、Token 状态更新、区块缺失检测、RPC 超时检测、WS 断连重连、区块重组处理、状态版本管理、数据源切换。

每次 Pool 状态记录：chain_id / pool_address / block_number / block_hash / state_version / updated_at / source_id / data_quality / sync_status。

### 4.4 数据一致性

同一条路线所有报价必须使用可解释的状态快照，禁止跨区块拼接虚假原子机会。不一致时标记 `STATE_MISMATCH`、禁止升级 VERIFIED、重新取数与报价。

### 4.5 性能指标

Block/Pool Update/RPC 延迟、WS 重连次数、缺块数、状态不一致数，P50/P95/P99。**先建立基线，再设硬目标。**

## 6. 多池多跳增量搜索引擎

### 6.1 核心要求

继续使用 Token–Pool 有向多重图 + 有界 DFS，不重写引擎，只升级效率与低竞争机会发现。

### 6.2 搜索范围（2–5 跳）

| 跳数 | 路线类型 |
|---|---|
| 2 | 双池跨池 |
| 3 | 三角、三池跨 DEX |
| 4 | 四跳闭环 |
| 5 | 五跳复杂闭环 |

要求：起终 Token 相同、Pool 不重复、中间 Token 不重复、每池属当前链、输入输出连续匹配、唯一指纹、镜像方向独立识别、不同报价版本不算新路线。

### 6.3 增量搜索升级

```
Pool 状态变化 → 识别受影响 Pool → Pool→Route 索引 → 识别受影响路线 → 仅重算 → 更新报价/净利/竞争评分
```

必须具备：`Pool→Route` 反向索引、`Route→Pool` 关联、路线/报价缓存、失效机制、任务优先级、超时、计算预算。

**冷热分级缓存（强制）**：路线缓存必须按历史命中与盈利表现分为**热 / 温 / 冷**三级，分级决定重算频率、缓存 TTL 与探索预算：
热路线优先重算并保持短 TTL；冷路线降低重算频率，但**不得被完全淘汰**（必须保留探索预算，避免只扫旧路线，见 §6.5）。
分级必须可观测（每级路线数、命中率、重算占比），且不得成为静默丢弃路线的机制。

### 6.4 搜索预算

候选数、图访问数、单轮时间、参与池数、最大跳数；超限标 `truncated=true`，不静默丢弃。

### 6.5 低竞争路线探索

兼顾历史盈利路线、高流动性路线、新发现 Pool、新 Token 组合、历史低竞争路线、未建立画像路线。保留探索预算，避免只扫旧路线。

## 7. AMM 精确报价与资金优化

### 7.1 报价原则

禁止简单现货价差、池中间价差、忽略流动性的理论价、未处理 Tick 的 V3 简化报价、多池价格相减。

### 7.2 支持能力

V2 恒定乘积、V3 集中流动性、V3 Tick 跨越、Aerodrome 波动池、StableSwap、Weighted AMM、多协议连续多跳报价。

### 7.3 七档资金

S1–S7 = 250 / 500 / 1,000 / 2,500 / 5,000 / 7,500 / 10,000 U。**逐档独立计算，禁止插值。**

### 7.4 投入规模优化

保留对数网格 + 黄金分割 + 整数精度复算。输出：最小/最优/最大可盈利本金、最优净利、最大净利率、资金容量曲线、盈亏平衡点。

## 8. 净利润与成本模型

### 8.1 双口径

```
net_token = 最终回款 − 初始投入
net_usd   = 最终回款美元 − 初始投入美元 − 显式执行成本
```

最终可执行判定以 `net_usd` 为准。

### 8.2 成本组成

AMM 手续费、滑点、Gas、Priority Fee、闪电贷费、延迟风险准备金、MEV 风险准备金、其他实际执行费用。**AMM 手续费与滑点已含在成交价，不重复扣减；现金成本单独计算。**

### 8.3 成本来源

链上 Gas、实际协议费率、配置闪贷费、历史交易费、竞争者实际支付费、系统准备金。**未知成本不得默认为 0。**

### 8.4 净利门槛（风控基线，不得放宽）

- 最低 DEX 净利润 2 USDC；
- 最低净利润率 10 bps（取 max）；
- 延迟/MEV 准备金不得被配置或前端降为 0；
- 门槛调整需独立风险评审。

## 9. REVM 与链上二次验证

### 9.1 核心架构

**链下搜索 + REVM 完整模拟 + 链上只读二次验证。**

| 层级 | 职责 |
|---|---|
| 链下搜索 | 发现路线、报价、资金优化 |
| REVM | 完整 EVM 执行模拟 |
| 链上只读验证 | Quoter、eth_call、状态与结果复核 |

### 9.2 模拟体系

M0（理论报价初滤）、M1（本地模型同块一致性）、M2（REVM/Quoter 完整验证）、M2-TX（原子交易完整回放）、M3（压力与敏感性）。M3 不是链上竞争回放，不得替代历史审计。

### 9.3 REVM 完整模拟

准备：目标链/区块/区块上下文/合约代码/Storage/账户余额/Token/Pool/Router/calldata。记录：模拟状态、Gas Used、最终余额、每池状态变化、Revert 原因、回款、净利、区块与状态来源。

### 9.4 链上只读二次验证

`eth_call`、Quoter、只读方法、指定区块状态读取。验证：路线输入输出一致、AMM 报价接近、Pool 状态一致、Token 精度正确、回款满足最低利润、无协议特殊行为。不一致标 `CHAIN_VALIDATION_MISMATCH`，禁止 VERIFIED。

### 9.5 VERIFIED 规则

只有完成要求范围内的完整 M2 验证且满足偏差门槛，才授予 VERIFIED。只做 M1 不得伪装 M2；Quoter 局部复核不得宣称整笔已完整验证；M2-TX 未覆盖的协议必须标注限制。

## 10. 竞争者分析引擎（v2.2 核心新增）

### 10.1 模块定位

持续研究链上已发生的套利行为：谁在竞争、竞争什么、何时成交、成本多少、是否活跃、哪些路线竞争激烈、哪些未被覆盖。

### 10.2 竞争交易采集

从 Base/Arbitrum 历史链上交易识别套利活动，记录：chain_id / tx_hash / block / tx_index / sender / recipient / contract / token_path / pool_path / protocol_path / gas_used / effective_gas_price / priority_fee / status / revert_reason / profit_estimate / detection_confidence。

### 10.3 竞争者识别

地址/合约画像、多地址关联、重复路线、交易模式、Gas 竞价习惯、成功率统计。**一个地址 ≠ 一个机器人**；竞争者识别必须有可信度等级。

### 10.4 竞争强度分析

24h/7d/30d 竞争交易数、活跃竞争地址数、聚类数、成功/失败数、平均 Gas、Priority Fee 分布、平均成交间隔。

### 10.5 竞争等级

`LOW_COMPETITION` / `MEDIUM_COMPETITION` / `HIGH_COMPETITION` / `INSUFFICIENT_DATA` / `RANK_VOLATILE`。必须可展开看具体数据，不能只按地址数量分类。

### 10.6 竞争者路线画像

常用 Token/Pool/DEX/跳数、成交频率、平均 Gas、Priority Fee、成功率、失败率、活跃时段、最近活跃时间。

### 10.7 竞争者变化检测

新竞争者进入、活跃度突变、开始用新路线、竞价成本显著增加、低竞争路线突然大量成交、高竞争路线长期无人参与 → 更新竞争等级。

## 11. 机会存活时间与竞争归因

### 11.1 生命周期

```
DISCOVERED → QUOTED → RISK_CHECKED → M2_PENDING
→ M2_VERIFIED/M2_REJECTED → COMPETITION_EVALUATED
→ ACTIONABLE/WATCH/REJECTED → PAPER_SUBMITTED
→ PAPER_FILLED/PAPER_MISSED/PAPER_EXPIRED
```

每阶段记录时间戳。

### 11.2 存活时间

记录首次发现/报价/M2 开始/完成/竞争评估/模拟提交/最后可盈利/首次失去盈利能力时间。

```
存活时间 = 首次失去盈利能力 − 首次发现
```

数据不足标未知，不估算冒充。

### 11.3 失败归因（12 类）

`DISCOVERY_TOO_SLOW` / `QUOTE_TOO_SLOW` / `M2_TOO_SLOW` / `STALE_STATE` / `COMPETITOR_FILLED_FIRST` / `GAS_COST_TOO_HIGH` / `PRIORITY_FEE_TOO_HIGH` / `PROFIT_BELOW_THRESHOLD` / `LIQUIDITY_INSUFFICIENT` / `SIMULATION_REVERTED` / `DATA_INCOMPLETE` / `UNKNOWN`。据此判断下一步优化速度/数据/模拟/竞价。

## 12. 交易排序与动态竞价研究

### 12.1 目标

建立 Base/Arbitrum 独立交易排序成本模型。本阶段只研究与模拟，不发送真实交易。

**范围边界（显式）**：nonce 分配、提交状态跟踪、替换交易（replacement）与失败成本冲销属于**实盘提交链路**，
归入 PH10 实盘准备（V22-1002 / V22-1003），本版本不实现；本版本只做竞价方案模拟与 EV 决策，
不得以"模拟提交"名义实现真实签名或广播。失败成本按 §8.2 与 §15.3 建模。

### 12.2 Base / Arbitrum 模型

Base 研究区块排序、RPC 提交延迟、费用、区块容量、竞争者成交费用、机会窗口。Arbitrum 研究 PGA、Priority Fee、Fast Feed、排序信息、竞价成本与成交概率关系。Fast Feed 只作观察，不保证插队。

### 12.3 期望收益（EV 决策器）

```
期望净收益 = P(成功)×成功净利 − P(失败)×失败成本 − 额外竞价成本
```

`P(成功)` 必须来自历史统计或标注为假设；失败成本含回滚 Gas；竞价成本按链模型计算。

### 12.4 决策结果

`COMPETE` / `WATCH` / `SKIP` / `INSUFFICIENT_DATA`。高竞争机会不因毛利润高就自动参与。

## 13. 机会质量评分与统一排序

### 13.1 评分目标

统一机会质量评分，不按毛利润排序。

### 13.2 评分维度

历史净利（30/90/180/365 天）、机会频率、竞争强度、存活时间、资金容量、执行可信度（M2/M2-TX）、数据质量、Token 风险、失败成本。

### 13.3 排名

历史累计净利、日均净利、机会频率、低竞争、资金容量、执行可信度、期望净收益。每种排名说明时间范围与样本量。

### 13.4 动态资源调度

按历史净利、频率、竞争强度、容量、最近表现、新路线探索价值调度。低竞争路线可更高优先级，但不停止热门路线监控。历史排名不等于未来收益。

## 14. 历史数据审计升级

### 14.1 目标

从“统计本机记录”升级为“基于真实历史链上状态的套利机会重建”。

### 14.2 历史回放

历史区块获取、区块内交易顺序重放、Pool/Token 状态恢复、历史报价、路线搜索、M2 模拟、Gas 计算、竞争者成交分析。**禁止用区块结束价冒充区块内交易前价。**

### 14.3 审计周期

30 / 90 / 180 / 365 天。

### 14.4 审计资金与输出

七档独立测试，标准审计资金 5,000 USDC。每条路线输出：出现次数、有效机会次数、历史/日均/月均净利、资金容量、平均 Gas、竞争者成交次数与成本、平均存活时间、数据完整度、M2 成功率。

### 14.5 数据质量

样本不足标 `INSUFFICIENT_DATA`。历史模拟结果与真实链上已实现利润分开显示。

## 15. Paper Trading 竞争模拟升级

### 15.1 流程

```
实时发现 → 报价与资金优化 → M2 模拟 → 竞争评估
→ 模拟提交 → 等待链上状态 → 判断是否仍有效 → 模拟成交/失败 → 计算最终净利
```

### 15.2 模式与成交判定

Base/Arbitrum 独立模拟 + 双链汇总报告。成交判定考虑提交时机会状态、后续 Pool 变化、模拟延迟、Gas、竞价成本、竞争者成交、机会过期、模拟结果。**不得把“提交时有利润”认定为“最终成交有利润”。**

### 15.3 模拟结果

提交/成交/错过/回滚次数、失败成本、成交率、净利、日均净利、最大回撤、资金使用率。

### 15.4 账户隔离

Base/Arbitrum 账户独立，资金不跨链共用。保留复式记账、费用账户、库存快照、审计。
