# DEX 原子套利执行合约
## 详细设计与安全规格（v1.0）

**状态：设计评审稿，未编码、未部署、未审计**  
**适用范围：同链 DEX 原子三角套利及原子跨池套利**  
**不适用范围：CEX 下单、跨链交易、跨交易所原子结算**

---

## 1. 设计目标

执行合约只负责同一条 EVM 链内的原子套利执行，不负责调用 CEX API，也不负责跨链转账。

主要目标：

1. 限制交易计划只能调用预先批准的 Token、DEX Adapter、Pool 和 Funding Provider。
2. 闪电贷借款、DEX 路由、偿还和最低利润检查在同一笔 EVM 交易中完成。
3. 任何交易腿失败、最低输出不满足、还款不足或最低利润不满足时，整笔交易回滚。
4. 限制回调入口、重复执行、Nonce 重放、重入、任意外部调用和资金转移。
5. 将链上可验证的最低回款保护与链下完整成本评估结合。
6. 保持合约接口足够简单，减少第一版审计面。

**重要限制：交易回滚不意味着没有损失。** 已广播交易执行失败，仍可能产生 Gas 费用；合约安全也不能消除排序竞争、RPC 错误、链故障或 Token 本身的风险。

## 2. 合约组件

### 2.1 ArbExecutor

核心执行合约，负责：

- 验证交易计划。
- 检查权限、Nonce 和有效期。
- 检查 Chain ID。
- 检查 Token、Pool 和 Adapter 白名单。
- 记录执行前基准余额。
- 调用自有资金执行路线或启动闪电贷。
- 控制回调状态。
- 验证最终回款和最低利润。
- 记录成功事件。

不允许用户提供任意目标合约地址并直接执行 `call`。

### 2.2 DexAdapterRegistry

负责管理经过验证的 DEX Adapter。

每个 Adapter 记录：

- Adapter 地址。
- 协议标识和版本。
- Factory 地址。
- Router 或 Pool 访问方式。
- 允许的 Chain ID。
- Adapter 代码哈希或版本标识。
- 启用状态。
- 审计记录。

更改 Adapter 白名单属于高风险管理操作。

### 2.3 TokenRegistry

负责管理允许交易的 Token：

- Token 地址。
- Chain ID。
- Decimals。
- 标准类型。
- 风险等级。
- 是否允许作为起始资产。
- 是否允许作为中间资产。
- 是否允许闪电贷。
- 是否具有特殊转账行为。
- 启用状态。

默认拒绝未验证的 Fee-on-Transfer、Rebasing、可暂停、可冻结或其他非标准 Token。确需支持时必须进行独立适配和测试。

### 2.4 FundingProviderRegistry

记录允许使用的闪电贷提供方：

- Provider 类型。
- Provider 地址。
- Chain ID。
- 允许借款 Token。
- 最大借款金额。
- 回调类型。
- Adapter 地址。
- 当前启用状态。

不得仅凭回调参数声称的 Provider 身份就信任回调。

### 2.5 Funding Receiver Adapters

第一版采用独立的 Provider 回调适配器：

- `AaveV3ReceiverAdapter`
- `ERC3156ReceiverAdapter`

不同提供方的 ABI、参数语义和偿还方式可能不同，不允许假定一个回调函数就能直接兼容所有协议。

第一版优先实现 Aave V3 单资产闪电贷和 ERC-3156 单资产闪电贷适配。其他提供方作为独立扩展，不直接复用未经验证的代码。

### 2.6 Treasury / Recovery Module

负责资金回收、利润归集和受限提款。

安全要求：

- 管理员权限与执行权限分离。
- 资金只能转给指定 Treasury 地址。
- 不允许任意地址提款。
- 不允许执行过程中转出资产。
- 不允许提款影响正在进行的闪电贷偿还。
- 紧急回收仅适用于非执行状态下的可回收余额。
- 执行所需 Token 和未偿还借款金额必须受到保护。

## 3. 执行模式

### 3.1 自有资金原子套利

基本流程：

1. `executeWithOwnCapital(plan)` 接收交易计划。
2. 检查调用者权限和计划签名。
3. 检查 Chain ID、Nonce、截止时间和计划哈希。
4. 检查起始 Token、数量、路线及白名单。
5. 记录起始 Token 的执行前余额。
6. 逐腿调用经过批准的 DEX Adapter。
7. 每一腿都检查最低输出。
8. 所有交易完成后，读取最终余额。
9. 验证最终余额不少于原始基准余额加最低利润。
10. 写入事件并返回成功。

最终保护条件：

`finalBalance >= initialBalance + minProfit`

如果不满足，整笔交易回滚。

### 3.2 闪电贷原子套利

基本流程：

1. 授权执行账户提交计划。
2. Executor 校验计划及所有风险边界。
3. 记录借款前起始资产的基准余额。
4. Executor 向登记的 Provider 发起闪电贷。
5. Provider 将资金转入 Receiver / Executor，并触发对应回调。
6. Receiver 验证 Provider、Initiator、Token、Amount、Fee 和参数哈希。
7. 执行预先批准的 DEX 路由。
8. 检查最终回款是否足够偿还本金和费用，并满足最低利润。
9. Receiver 对 Provider 只授权精确应还金额。
10. Provider 按协议约定拉取本金和费用。
11. Provider 正常完成，交易成功；任何一步失败则整笔交易回滚。

### 3.3 单资产优先

第一版闪电贷优先采用单资产模式：

- 单一借款 Token。
- 单一借款金额。
- 起始和最终回款资产相同。
- 整个路线返回借款资产。
- 不实现多资产组合借款。
- 不实现跨链借款。

多资产借款增加回调、资产核算和风险检查复杂度，只有在历史审计证明有实际必要时才考虑。

## 4. 闪电贷回调设计

### 4.1 Aave V3 适配

Aave V3 使用自身 Receiver 接口和 `executeOperation(...)` 回调，不可将其直接当作 ERC-3156 回调。

必须校验：

- `msg.sender` 是已登记且指定 Chain ID 的 Aave Pool。
- `initiator` 是本 Executor。
- `asset` 与交易计划的借款 Token 一致。
- `amount` 与记录的借款数量一致。
- `premium` 是回调提供的费用。
- `params` 的哈希与当前交易计划一致。
- 执行状态处于预期的等待回调状态。
- 回调只能被成功处理一次。

Aave V3 的偿还方式要求 Receiver 在执行完成前为 Pool 提供本金和 Premium 对应的授权，由 Pool 在回调完成后按协议流程拉取资金。授权必须精确到应还金额，不能永久保留无限额度。

### 4.2 ERC-3156 适配

ERC-3156 使用：

`onFlashLoan(initiator, token, amount, fee, data)`

必须校验：

- `msg.sender` 为登记的 ERC-3156 Lender。
- `initiator` 为本 Executor。
- Token、Amount 和 Fee 与当前执行记录一致。
- Data 哈希与当前计划一致。
- 当前执行状态允许该回调。
- 返回值必须符合 ERC-3156 约定的 Callback Success Magic Value。

回调结束前只给 Lender 提供精确应还金额的授权。

### 4.3 禁止“万能回调信任”

回调参数本身不是天然可信数据。

只有在确认调用方是对应的可信 Provider，并验证 Initiator 和当前计划后，才能信任相关借款参数。

不同 Provider 必须拥有独立适配器、独立测试和独立启用开关。

## 5. 交易计划结构

链下策略引擎生成交易计划，执行前签名并传入合约。

计划字段建议：

- `chainId`
- `executor`
- `strategyId`
- `opportunityId`
- `nonce`
- `deadline`
- `startToken`
- `amountIn`
- `minProfit`
- `fundingProvider`
- `fundingToken`
- `fundingAmount`
- `maxGasPrice`
- `maxBlockNumber`
- `routeHash`
- `legs`
- `signer`
- `signature`

每条交易腿包含：

- `protocolId`
- `adapter`
- `pool`
- `tokenIn`
- `tokenOut`
- `amountIn` 或可验证的数量计算方式
- `minAmountOut`
- `feeTier` 或协议参数
- `legDataHash`

不得允许不受限制的任意 `target`、`calldata` 或 `delegatecall`。

### 5.1 签名和重放保护

建议使用 EIP-712 结构化签名。

签名域至少绑定：

- Chain ID。
- Executor 地址。
- 结构化类型版本。

交易计划必须绑定：

- 唯一 Nonce。
- 有效截止时间。
- 路线哈希。
- Token 和金额。
- Funding Provider。
- 最低利润。

同一 Nonce 不可重复执行。过期计划不可执行。切换链或切换 Executor 后，旧签名不可复用。

### 5.2 参数约束

- `deadline` 必须在允许的短时间窗内。
- `maxBlockNumber` 不能超出可接受的执行区块范围。
- `maxGasPrice` 作为执行环境保护条件。
- 每腿 `minAmountOut` 必须大于零并符合路线要求。
- 最终利润必须采用起始 Token 计价。
- 计划的借款金额不得超过 Provider 可借额度及系统风险上限。

完整 USD 净利润依赖链下价格源和实际 Gas 成本，链上合约的最低利润检查只保护链上可验证的资产回款。

## 6. 内部状态机与重入保护

建议状态：

- `IDLE`
- `PLAN_VALIDATED`
- `AWAITING_FLASH_CALLBACK`
- `EXECUTING_ROUTE`
- `REPAYMENT_READY`
- `COMPLETED`
- `PAUSED`

状态转换示例：

`IDLE → PLAN_VALIDATED → AWAITING_FLASH_CALLBACK → EXECUTING_ROUTE → REPAYMENT_READY → COMPLETED → IDLE`

任何不符合当前状态的调用均应拒绝。

特别要求：

- 不能在普通执行状态重复进入闪电贷回调。
- 不能让外部调用者伪造 Provider 回调。
- 不能重复消费同一个交易计划。
- 不能在执行期间提款。
- 不能通过嵌套调用创建第二笔并行执行。
- 不能因回调机制需要而简单移除所有重入保护。

闪电贷回调本身是预期的嵌套调用，应通过明确的状态机和调用方校验控制，而不是机械地用一个通用 `nonReentrant` 修饰器包住所有入口。

## 7. DEX 路由与 Pool 安全

### 7.1 Adapter 优先

核心合约只调用经过登记的 Adapter。

Adapter 负责处理各协议的：

- Swap 调用方式。
- Pool 地址验证。
- 费率参数。
- 输出数量。
- 回调验证。
- 特殊协议数据。

不允许在核心 Executor 中堆叠大量未经隔离的协议特例。

### 7.2 Uniswap V3 类回调

涉及 V3 风格 Swap Callback 时，必须：

1. 验证回调调用者是对应 Factory 派生或登记的合法 Pool。
2. 验证 Token Pair 和 Fee Tier。
3. 验证当前执行上下文确实期待此回调。
4. 校验回调支付 Token 与当前交换方向一致。
5. 不允许未授权 Pool 冒充合法池触发回调。

### 7.3 Hook 和特殊协议

V4 Hook、特殊回调协议和定制化 AMM 必须独立审计：

- Hook 地址及代码哈希。
- Hook 回调次序。
- 外部状态变化。
- Token 转账行为。
- 回调期间可能发生的外部调用。
- 最终资产余额。

在没有独立适配器和测试前，拒绝执行。

## 8. Token 兼容与授权

### 8.1 Token 兼容

第一版默认仅接受经验证的常规 ERC-20 Token。

需要拒绝或单独验证：

- Fee-on-Transfer。
- Rebasing。
- Blacklist / Freeze。
- 可随意修改转账逻辑的代理 Token。
- 无法正常返回 ERC-20 布尔值的特殊 Token。
- 存在回调或不寻常转账副作用的 Token。

使用安全 Token 传输封装，并在关键步骤读取实际余额变化，而不是只相信函数返回值。

### 8.2 授权控制

- 不设置无限授权。
- 只授权本次执行所需数量。
- 授权对象必须是登记的 Provider 或 Adapter。
- 不允许任意用户更改授权对象。
- Provider 拉取还款后检查授权和余额状态。
- 对特殊 Token 使用单独适配规则。

### 8.3 Dust 处理

不依赖合约内残余 Dust 产生收益。

- 执行前后记录指定资产余额。
- 只将本次交易所产生的净增量视为本次结果。
- 不将历史残余资产计入套利利润。
- Dust 回收只能由受限 Treasury 管理流程执行。

## 9. 权限和管理控制

角色建议：

- `DEFAULT_ADMIN_ROLE`：管理权限。
- `OPERATOR_ROLE`：提交有效交易计划。
- `PAUSER_ROLE`：暂停执行。
- `TREASURY_ROLE`：执行受限资金归集。
- `CONFIG_ROLE`：变更白名单和参数。

安全要求：

1. 核心资金权限不能与普通 Operator 共用。
2. 第一阶段主网部署前应采用多签管理关键权限。
3. 白名单修改、Provider 地址修改和 Treasury 修改必须有完整审计日志。
4. 高风险参数变更建议采用 Timelock。
5. 暂停权限应能快速生效。
6. 恢复交易必须检查风险事件是否已消除。
7. 管理员不得直接通过任意外部调用绕过 Executor 的安全边界。

### 9.1 暂停规则

以下情况应拒绝新执行：

- 已触发全局暂停。
- Chain ID 与计划不符。
- Provider 被禁用。
- Adapter 被禁用。
- Token 被禁用。
- 交易计划过期。
- Nonce 已使用。
- 交易计划签名不合法。
- 执行状态不为空闲。
- 当前 Gas Price 超限。
- 路线或最终利润条件不满足。

## 10. 资金归集与紧急恢复

提款规则：

- 只能从非执行状态进入。
- 只能转往预设 Treasury。
- 必须保留任何未偿还债务。
- 不能提取本次正在使用的闪电贷资产。
- 不允许通过 Recovery 接口绕过借款偿还。
- 管理操作必须记录事件。

当发现合约漏洞、Provider 异常、DEX Adapter 异常或 Token 行为异常时：

1. 停止新执行。
2. 禁用相关 Provider、Adapter 或 Token。
3. 评估未完成交易。
4. 检查合约持有资产和授权。
5. 根据专项审计流程恢复资金。
6. 修复并重新测试后才允许恢复。

不能把紧急提款接口设计为任何情况下均可任意转走合约资产。

## 12. CEX–DEX 相关的合约边界

CEX–DEX 策略不允许在 EVM Executor 中尝试执行 CEX 网络订单。

原因：

- EVM 交易不能等待中心化交易所订单撮合。
- CEX 订单与链上交易没有共同原子提交机制。
- 闪电贷资金必须在同一交易流程中完成偿还，不能跨越链外等待。
- CEX 成交可能部分完成或状态未知。

因此：

- DEX Executor 只执行 DEX 链上交易腿。
- CEX 订单由链下 Exchange Adapter 管理。
- 两边由统一 Hedge State Machine 协调。
- CEX–DEX 风险由链下风险引擎和库存管理器处理。
- 不允许以合约最低回款检查替代 CEX–DEX 的完整双腿风险检查。

## 13. 第一版合约测试清单

### 正常路径

- 自有资金套利闭环。
- 单资产闪电贷闭环。
- 最低利润满足。
- Provider 正常拉款。
- 交易成功后资产和事件一致。

### 参数攻击

- 错误 Chain ID。
- 过期 Deadline。
- 重复 Nonce。
- 非法签名。
- 错误 Token。
- 错误 Amount。
- 错误 Provider。
- 错误 Pool。
- 错误 Adapter。
- 最低输出人为降低。
- 路线哈希不一致。

### 回调攻击

- 伪造 Provider。
- 伪造 Initiator。
- 伪造 Premium / Fee。
- 重复回调。
- 非预期状态回调。
- 恶意 Callback Data。
- 利用回调嵌套执行其他计划。

### 资金安全

- 偿还金额不足。
- 最低利润不足。
- Token 转账失败。
- 非标准 Token 行为。
- 授权不足。
- 残余 Dust。
- 执行过程提款。
- 紧急暂停期间新执行。

### DEX 风险

- 池地址伪造。
- Factory 验证失败。
- V3 回调调用者伪造。
- 路由中途输出不足。
- 池状态变化。
- Hook 或特殊回调行为。
- Router / Adapter 版本变化。

### 测试方法

- 单元测试。
- 集成测试。
- Fuzz Testing。
- Invariant / Property Testing。
- 本地 EVM Fork。
- 多 Provider 回调集成测试。
- 失败交易 Gas 测试。
- 第三方安全审查。

合约未完成上述测试和独立审计前，不得进入主网实盘准入。

## 14. 部署策略

第一阶段仅：

- 本地合约编译。
- 本地 EVM 测试。
- Fork 环境执行。
- 接口和字节码记录。
- 代码哈希登记。
- 安全测试报告。

不部署主网实盘 Executor，不启用真实签名。

未来主网部署应当每条链独立部署、独立配置、独立验证：

- Chain ID。
- Provider。
- DEX Factory / Router。
- Adapter。
- Token。
- Treasury。
- 权限角色。
- 代码哈希。
- 合约版本。

不应因为某条链已通过审计，就默认其他链上的部署地址和协议版本也安全。
